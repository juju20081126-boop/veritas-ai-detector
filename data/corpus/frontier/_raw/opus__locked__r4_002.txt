Flutter's performance comes mainly from its architecture, which avoids several bottlenecks found in other cross-platform frameworks.

**Compiled to native code**
In release mode, Dart is compiled ahead-of-time (AOT) into native ARM or x86 machine code. There's no JavaScript interpreter at runtime, which leads to fast startup and consistent execution speed. During development, just-in-time (JIT) compilation enables hot reload instead.

**Its own rendering engine**
Flutter doesn't use platform UI components. It draws every pixel itself using its rendering engine (Impeller on iOS and newer Android versions, Skia previously). This avoids the overhead of translating to native widgets and gives predictable, consistent frame rendering at 60 or 120 fps across devices.

**Efficient widget system**
Widgets are lightweight, immutable descriptions of the UI. Flutter compares widget trees and only updates the underlying element and render objects that have changed. Developers can optimize further with `const` constructors, splitting large widgets, and `RepaintBoundary` to isolate expensive repaints.

**Concurrency**
Heavy tasks can run in isolates, separate memory threads, so parsing or computation doesn't block the UI thread.

**Tooling**
Flutter DevTools provides frame timing charts, CPU and memory profiling, and widget rebuild tracking to identify jank.

**Compared to other frameworks**
- **React Native** historically relied on a JavaScript bridge to native components, which could cause latency; its newer architecture (JSI, Fabric) narrows the gap.
- **Native (Swift/Kotlin)** still offers the most direct platform access and smaller app sizes.
- **Flutter's trade-offs** include larger binaries and UI that doesn't automatically match platform conventions.

Overall, Flutter delivers near-native performance for most apps.
